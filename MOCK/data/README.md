# Mock data

- `mock_postings.json`은 공고 30건을 API 응답용 camelCase 구조로 정규화한 실행 데이터입니다.
- `mock_recommendations.json`은 추천 30건을 정규화한 실행 데이터입니다. Spring 내부 식별자는 포함하지 않고 공고 데이터의 `externalCompanyId`로 연결합니다.

원본 공고에는 학력, 주요 업무, 자격요건, 우대사항, 자기소개서 문항이 없습니다. 학력·주요 업무·우대사항은 각각 `null` 또는 빈 배열로 제공하고, 자격요건은 원본 키워드로부터 데모 문구를 만들었습니다. 모든 공고에서 지원 프로젝트와 초안 생성 흐름을 바로 검증할 수 있도록 공고 30건에 데모 문항을 2개씩 추가했습니다. `jobTitle`은 추천 원본의 짧은 직무명으로 통일하고 `jobCategory`는 이를 기준으로 데모용 범주를 부여했습니다.

두 파일은 실행 중 변경하지 않습니다. 데이터를 갱신할 때는 공고 ID, 기업 외부 ID 및 추천 결과 간 참조가 유지되도록 함께 갱신해야 합니다. 서버는 시작 시 중복 공고·순위, 잘못된 추천 참조 및 공고에 없는 일치 키워드를 검사하고 문제가 있으면 즉시 시작에 실패합니다. 추천 API는 이 고정 데이터 중 `신입`과 `경력무관` 공고만 점수순으로 반환하고 순위를 다시 부여합니다.

자기소개서 문항을 추가할 때는 백엔드 저장 기준에 맞춰 `questionOrder`를 공고 안에서 중복 없이 1부터 부여하고, `questionText`는 1~1,000자, `charLimit`은 생략하거나 1~5,000 범위로 작성합니다. 공고에 문항이 없으면 `questions`를 빈 배열로 유지하며, 이 공고로 지원 프로젝트를 만들 때 백엔드 요청에 `manualQuestions`가 필요합니다.
