# MVP 사용자 흐름

비로그인 공고 탐색, 로그인 후 경험 기반 맞춤 추천, 공고별 자기소개서 초안 작성을 하나의 흐름으로 정의합니다.

## 1. 시스템 경계

```text
Mock Posting API Server
└─ 비로그인 공고 목록·상세와 공고에 포함된 자기소개서 문항 제공

Spring Boot API
├─ 데모 로그인과 사용자 식별
├─ 경험 구조화·저장
├─ 저장된 경험 기반 맞춤 추천 결과 제공
├─ 지원서·문항 스냅샷 저장
└─ AI 초안 생성 상태·수정본 저장
```

- 공고 마스터와 공고 수집 배치는 구축하지 않습니다.
- 기업·직무·업종·키워드는 공고 원본의 읽기 전용 정보입니다.
- 맞춤 추천 로직은 구현 범위 밖이며 Spring API는 목 추천 결과 계약을 제공합니다.
- 초안 생성은 SSE가 아니라 `202 Accepted`와 상태 조회 Polling을 사용합니다.

## 2. F-A — 신규 사용자: 전체 공고에서 첫 초안 생성

1. 비로그인 사용자가 서비스에 접속합니다.
2. 프론트엔드는 Mock Posting API의 전체 공고 목록을 호출합니다.
3. 사용자가 검색·필터 후 공고 상세를 확인합니다.
4. 사용자가 `[지원하기]` 또는 `[자소서 작성]`을 누릅니다.
5. 비로그인 상태이면 프론트엔드가 `externalPostingId`를 세션에 보관하고 로그인 화면을 표시합니다.
6. 로그인 버튼을 누르면 데모 사용자로 로그인되고 기존 공고의 작성 화면으로 돌아옵니다.
7. 저장된 경험이 없으면 경험 등록 화면으로 이동합니다.
8. 사용자가 자유서술 경험을 LLM 구조화 API로 변환하고 결과를 확인한 뒤 저장합니다.
9. 작성 화면으로 돌아와 기업·직무 정보를 읽기 전용으로 확인하고 경험 1~3개를 선택합니다.
10. 공고 상세에 자기소개서 문항이 있으면 이를 사용합니다.
11. 공고에 문항이 없으면 사용자가 문항과 목표 글자 수를 직접 입력합니다.
12. 프론트엔드는 지원서 생성 API로 공고와 문항 스냅샷을 저장합니다.
13. 문항별 초안 생성 API를 호출하고 반환된 상태 URL을 Polling합니다.
14. 완료된 초안을 편집·저장하거나 클립보드로 복사합니다.

경험 등록은 모달형 빠른 추가가 아니라 전체 구조화·확인·저장 흐름을 사용합니다.

## 3. F-B — 재방문 사용자: 맞춤 추천에서 초안 생성

1. 사용자가 데모 로그인합니다.
2. 저장된 경험이 한 건 이상이면 프론트엔드가 맞춤 추천 생성 API를 호출합니다.
3. Spring은 저장된 경험을 기준으로 구성된 목 추천 결과를 반환하고 저장합니다.
4. 사용자가 추천 목록과 공고 상세를 확인합니다.
5. `[지원하기]`를 누르면 작성 화면으로 이동합니다.
6. 기존 경험 1~3개를 선택합니다.
7. 공고 문항이 있으면 사용하고, 없으면 문항을 직접 입력합니다.
8. 지원서와 문항을 생성한 뒤 초안 생성을 요청합니다.
9. 상태 Polling 완료 후 초안을 편집·저장·복사합니다.

## 4. API 호출 순서

### 비로그인 공고 탐색

```text
GET {MOCK_POSTING_API_BASE_URL}/api/v1/postings
→ GET {MOCK_POSTING_API_BASE_URL}/api/v1/postings/{externalPostingId}
```

### 로그인과 경험 등록

```text
POST /api/v1/auth/demo-login
→ POST /api/v1/experiences/structure
→ POST /api/v1/experiences
```

### 경험 기반 맞춤 추천

```text
POST /api/v1/recommendations
→ GET /api/v1/recommendations
→ GET /api/v1/recommendations/{recommendationId}
```

### 지원서와 초안

```text
POST /api/v1/job-applications
→ POST /api/v1/cover-letter-items/{coverLetterId}/drafts
→ GET /api/v1/cover-letter-drafts/{draftId} 반복
→ PUT /api/v1/cover-letter-drafts/{draftId}/edit
```

## 5. 문항 선택 규칙

```text
공고 문항이 한 건 이상 존재
→ 공고 문항을 읽기 전용으로 표시하고 그대로 스냅샷 저장

공고 문항이 없음
→ 사용자가 문항을 한 건 이상 입력
→ 입력한 문항을 스냅샷 저장
```

공고 문항이 있는데 클라이언트가 임의 문항을 함께 보내면 `422 QUESTIONS_ALREADY_PROVIDED`를 반환합니다. 공고 문항이 없고 사용자 입력도 없으면 `422 MANUAL_QUESTION_REQUIRED`를 반환합니다.

## 6. 주요 예외 흐름

| 상황 | 처리 |
|---|---|
| 비로그인 상태에서 작성 시도 | 공고 ID 보관 후 로그인 화면 표시 |
| 경험 없이 맞춤 추천 요청 | `422 EXPERIENCE_REQUIRED` |
| 경험 구조화 실패 | 원문 유지 후 다시 시도 |
| 공고 문항과 직접 입력 문항이 모두 없음 | 문항 입력 오류 표시 |
| 초안 생성 중 | 버튼 비활성화, 상태 Polling |
| 초안 생성 실패 | 입력값 보존, 새 초안으로 재시도 |
| 글자 수 초과 | 경고하되 수정본 저장 허용 |
| Mock Posting API 장애 | 오류 안내 후 재시도 |

## 7. 범위 밖 기능

- 사람인·잡코리아 실제 API 연동
- 공고 자체 DB와 수집 배치
- 실제 맞춤 추천 점수 계산
- Google OAuth와 비밀번호 검증
- SSE 스트리밍
- 기업·직무·업종·키워드 수정
